# 算法引擎升级提案

**变更名称**: algorithm-engine-upgrade  
**创建日期**: 2026-05-05  
**状态**: 待批准

---

## 背景

当前物流路径规划系统已经具备较完整的优化引擎框架，但整体仍偏向教学演示和原型验证，距离工程级、企业级决策系统还有明显差距。

### 当前主要问题

| 问题 | 说明 |
|------|------|
| 多目标优化精度低 | 当前主要依赖简单加权求和和基础 Pareto 排序，缺少工程级 NSGA-II/III 路线算子 |
| 距离数据不统一 | 虽已完成高德 API 距离缓存，但多数求解器仍在使用欧氏距离或 Haversine 修正距离 |
| 求解器智能不足 | 缺少根据问题规模、约束类型、实时性要求自动推荐求解器的能力 |
| 缺乏统一质量评估 | 没有系统化输出 gap、可行性、Pareto 质量、距离精度等指标 |
| 前端决策支持较弱 | 多目标结果展示偏简单，缺少真正可辅助选择的 Pareto 可视化 |

---

## 目标

### 核心目标

1. **统一精确距离底座**：所有求解器优先使用高德缓存的真实道路距离
2. **提升多目标优化质量**：实现适用于 VRP 的 NSGA-II/III 路线感知算子
3. **建立求解器智能推荐机制**：根据问题类型与规模推荐合适求解器
4. **建立统一结果评估体系**：让每次优化结果都可量化评估
5. **增强前端决策可视化**：让用户能真正看懂并选择 Pareto 解

### 非目标

- 本次不重构数据库核心业务模型
- 本次不引入全新的商用求解平台
- 本次不直接做强化学习在线训练平台
- 本次不先做超大规模分布式优化集群

### 包含

- [ ] OR-Tools / Gurobi / PyVRP / pymoo / ALNS / GA 等求解器升级

## 影响评估

| 影响范围 | 影响程度 | 说明 |
|----------|----------|------|
| 后端服务层 | 高 | 优化引擎核心逻辑会升级 |
| 前端可视化 | 中 | 多目标与对比页面增强 |
| 数据精度 | 高 | 精确距离将成为统一底座 |
| API | 中 | 新增统一求解、评估、精度报告接口 |
| 测试体系 | 高 | 需要新增基准测试与质量验证 |

---

## 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 高德 API 配额与时延限制 | 精确距离构建慢 | 使用缓存、批量矩阵、预热机制 |
| 自定义 NSGA 算子复杂 | 实现周期拉长 | 先落核心算子，再逐步扩展 |
| 多求解器升级导致行为不一致 | 结果不可比 | 统一问题构建器和评估器 |
| 前端图表复杂度提升 | 页面卡顿 | 使用采样、懒加载、分层展示 |

---

## 成功标准

- [ ] 所有主力求解器可接入统一精确距离矩阵
- [ ] 多目标优化输出真实 Pareto 前沿而非仅简单排序
- [ ] 系统可根据问题特征推荐求解器
- [ ] 结果中可查看可行性、gap、精度、Pareto 指标
- [ ] 前端可展示 Pareto 散点图、平行坐标图、求解器对比图
- [ ] 形成分阶段实施计划并可按 OpenSpec + SDD 执行
